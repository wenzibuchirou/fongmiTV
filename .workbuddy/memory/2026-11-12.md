# 2026-11-12

## 分析并修复「v7a 包在 Android 4.4 提示安装包解析失败」

结论：不是打包损坏，项目 `minSdk = 24`（README 与所有 git 历史均为 24），Android 4.4（API 19）不受支持。

两个解析期根因（都会让 4.4 的 PackageInstaller 显示「解析失败」）：
1. `minSdkVersion=24 > 19`，4.4 的 PackageParser 解析 `<uses-sdk>` 阶段直接判失败。
2. AGP 9.3.1 在 `minSdk >= 24` 时只签 v2，APK 内无 `META-INF/MANIFEST.MF`/`.SF`/`.RSA`；
   4.4 只认 v1 → `INSTALL_PARSE_FAILED_NO_CERTIFICATES`。
   `apksigner verify --min-sdk-version 19` 原包报 `DOES NOT VERIFY: Missing META-INF/MANIFEST.MF`。

其它老系统不兼容特征：3 个 dex 均为 `dex 037`、`extractNativeLibs=false` + 21 个 .so 全部 stored/页对齐、
60+ 个依赖库声明 minSdk 21/23（含 media3 全系 23）、targetSdk/compileSdk 37、Chaquopy 17 / Python 3.10 / libmpv。

真实构建实验（临时把 minSdk 改 19，已还原）：
- `:app:process...Manifest` 失败 `In order to use core library desugaring, please enable multidex.`
- 加 `multiDexEnabled true` 后 `:catvod` 同样报错（每个子模块都要改）
→ 硬降 minSdk 不可行；再往下要 `tools:overrideLibrary` 覆盖 60+ 库，且运行时必然崩。

已实施修复（仅消除第 2 个根因，不改变最低系统要求）：
- 根 `build.gradle` 新增 `signLegacyV1` 任务，`assembleRelease` 经 `finalizedBy` 自动触发；
  扫 `app/build/outputs/apk/**/release/*.apk`，用 apksigner 补 v1（保留 v2、关 v3/v4），输出 `Release/apk/*-v1.apk`。
  注意 Gradle 9 已移除 `Project.exec`，任务改用 `ProcessBuilder` 调 `java -cp apksigner.jar ...`。
- 已对 4 个现有 APK 补签并验证：按 `--min-sdk-version 19` 口径 v1=true/v2=true、
  `zipalign -c 4` OK、证书不变、minSdk 仍 24；`--dry-run` 确认任务图含 `:signLegacyV1`。
- 新增 `docs/ANDROID_44_COMPAT.md` 分析报告；README 增加相容性说明与文档链接。
  注意 `.gitignore` 含 `/docs`，新文档需 `git add -f` 才能提交。

重要边界：补 v1 **不能**让真 4.4 装上（仍卡 minSdk=24）。给 4.4 的可行方案：
换 Android 7.0+ 设备，或用专为 KitKat 适配的 FongMi/TV 早期 fork（OK TV KitKat / FusionTV-KitKat 系，
做了 MultiDex、IJK 播放、TLS1.2 补丁）；自行维护 legacy 分支等于重做整条依赖链。
