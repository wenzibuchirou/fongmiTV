## 新增「内置远程 JSON 配置」能力（asset:// 内置配置源）

需求：`app/src/main/java/com/fongmi/android/tv/api/config` 的远程 JSON 获取流程，支持把配置 JSON 打包进 APK 内置（离线可用），远程 JSON 形如 https://vod.com/vod.json。

原流程分析：
- `VodConfig.load()` / `LiveConfig.load()` → `Decoder.getJson(UrlUtil.convert(config.getUrl()), TAG)` 走 OkHttp 拉取 → `verify()`（base64/**、AES-CBC 2423 解密）/`fix()`（相对 .js 路径改写）→ 解析 sites/lives/parses 等。
- 配置只存 URL（`Config.url`），`Config.json` 字段未用于加载。
- `UrlUtil.convert` 已有 `assets://` scheme（转到本地 Nano 服务器，由 `Asset.open` 读 assets），但依赖本地 HTTP 回环。

本次实现（直接离线读 assets，不依赖回环）：
1. `api/Decoder.java`：新增 `isAsset(url)`、`getJsonFromAsset(url, tag)`、`assetName()`、`readString()`。asset(s):// 直接 `Asset.open(name)` 读取，复用 `verify()`，并以本地服务器地址为 base 让相对 .js 仍可解析。
2. `api/config/BaseConfig.java`：新增 abstract `getType()`；`builtInUrl()`（默认空）；`hasBuiltIn()`/`builtInConfig()`；`getJson(config, tag)` 统一入口（asset 走本地读，否则网络）。`ensureLoaded()` 增加：无配置时用内置；远程失败/结果为空且当前非 asset 时回退内置（catch 亦回退，避免递归）。
3. `VodConfig`：`getType()=VOD`、`builtInUrl()="assets://vod.json"`、`load()` 改用 `getJson()`。
4. `LiveConfig`：`getType()=LIVE`、`builtInUrl()="assets://live.json"`、`load()` 改用 `getJson()`。
5. `WallConfig`：实现 `getType()=WALL`（壁纸非 JSON，无内置）。
6. 新增 `app/src/main/assets/vod.json`、`live.json` 模板（含 notice 说明覆盖方式；结构含 sites/lives/parses/flags/rules/headers/hosts/ads/doh/proxy）。

用法：设置里配置地址填 `assets://vod.json`（手机端输入 `a` 会自动补 `ssets://`），即可完全离线加载内置 JSON；把 `https://vod.com/vod.json` 的内容覆盖 assets/vod.json 即可内置自己的远程配置。

验证：`:app:compileMobileArm64_v8aReleaseJavaWithJavac` BUILD SUCCESSFUL（24s）。

## 远程 JSON 本地缓存 + 内置默认源

需求：启动优先用本地缓存；缓存加载失败则重新拉远程；加载成功后后台比对本地与远程，不一致则拉远程覆盖本地。

实现：
1. 新增 `api/config/ConfigCache.java`：缓存目录 `App.get().getFilesDir()/config/`，文件名 `config_<md5(url)>.json`（持久化，非 cache 目录）。`read/exists/write/delete`，写入用 `.tmp` + rename 原子替换。
2. `BaseConfig`：
   - `getJson(config, tag)` 改为缓存优先：非 asset 时先读缓存（命中置 `FROM_CACHE`），否则 `Decoder.getJson` 拉取并写缓存。
   - 新增 `loadWithCache(config)`：先 `load`；若用的是缓存且抛异常（缓存内容不可用）→ `FORCE_REMOTE` 强制重拉并重写缓存；缓存命中且加载成功 → `scheduleRefresh(config)`。
   - `scheduleRefresh`：后台 `Task.execute` 拉远程，与本地缓存字符串比对，不一致则覆盖缓存文件（仅更新文件，不热重载，下次启动生效）；用 `AtomicBoolean refreshing` 防并发重复。
   - `ensureLoaded` 改用 `loadWithCache`。
   - 新增 `loadRemoteFirst(config)`：显式手动重载（`loadConfig`/选配置）先强制远程，失败且有缓存则回退缓存。
3. 内置默认源改为指定远程 URL（vod & live 共用）：
   `https://gh-proxy.com/https://raw.githubusercontent.com/wenzibuchirou/tvboxlist/master/jsm.json`
   即无配置时自动以该 URL 作为默认源，首次拉取并缓存，后续启动走缓存 + 后台同步。

注意：该 jsm.json 为完整 TVBox 配置（154 sites / 3 lives / 29 parses），含 50+ 相对引用（`./jar/spider.jar`、`./js/*.js`、`./json/*.json`、`./py/*.py` 等）。`Decoder.fix()` 会用 `UriUtil.resolve` 以该 URL 为 base 改写为绝对地址；已验证 `UriUtil.resolve` 保留 `https://` 前缀，且 gh-proxy 对 `jar/spider.jar`、`tvboxtv.txt` 均返回 200，可正常解析。

## 修复"点播为空"（配置从未加载）

根因（已定位）：`HomeActivity.initConfig()` 走的是 `VodConfig.get().init().load(callback)`，**不走 `ensureLoaded()`**。全新安装时 `Config.vod()` 返回一个 `url` 为空的 Config，`loadRemoteFirst()` 没有"空 URL → 内置源"的判断，`Decoder.getJson("")` 直接抛异常，最终 `callback.error("")` + `StateEvent.empty()`，首页点播自然为空。`builtInUrl()` 只在 `ensureLoaded()` 里生效，而启动路径根本不经过它。

修复：
1. `BaseConfig.loadConfig()`：加载前若 `config == null || TextUtils.isEmpty(config.getUrl())`，改用 `builtInConfig()`（并把 `this.config` 指向它），所有入口（HomeActivity / SettingActivity / Server Action）统一生效。
2. `BaseConfig` 新增 `fallbackUrl()/hasFallback()/loadFallback(config)` + `ThreadLocal FALLBACK_JSON`：远程内置源不可达时，解析 APK 内 `assets/vod.json` 离线副本，仍用原 Config 对象解析（home/parse 选择不串），并把内容写入 ConfigCache 供下次秒开。
3. `BaseConfig.ensureLoaded()` 重写为三段式：cache/remote → 内置源 → 离线 assets 兜底。
4. `Decoder.getJsonFromAsset()`：`Asset.open()` 返回 null 时抛明确异常（原来会 NPE）。
5. `VodConfig.initSite()` / `LiveConfig.initLive()`：`BaseLoader.parseJar()` 包 try/catch。原来 spider.jar（2MB）下载失败会直接中断整个配置解析 → 站点列表为空；现在失败不致命，用到时由 `JarLoader.getSpider` 惰性重试。
6. `assets/vod.json` 换成 jsm.json 的**预解析副本**（80 个 `./` `../` 相对引用全部改写为 gh-proxy 绝对地址，0 残留），154 sites / 3 lives / 29 parses，72KB。这样离线兜底时不会因相对路径指向 127.0.0.1 本地服务而失效。

验证：`assembleRelease` BUILD SUCCESSFUL in 6m47s；APK 内 `assets/vod.json`(72620B, 154 sites)；dex 含内置 URL 与 `assets://vod.json`；v2 签名 true。
